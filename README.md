# How to evaluate AI agents: grade the world, not the transcript

By [Michał Woliński](https://wolinski.com). Companion code for the article
[How to Evaluate AI Agents: Grade the World, Not the Transcript](https://wolinski.com/blog/how-to-evaluate-ai-agents.html).

An evaluation harness for a tool-using support agent. Every trial gets a fresh, seeded world (an
in-memory SQLite shop backend), the agent acts on it through six tools, and a **state grader** diffs
the database before and after: every required change happened, and nothing happened that the task
does not allow. It never reads what the agent said. A **transcript judge** (an LLM reading the
conversation) runs alongside it, so the two can be compared on the same episodes.

Every measurement in the article comes from a run committed under [`runs/`](runs). Together, those runs and their
re-grading experiments cost $2.64 in API calls, recomputed from the `usage` recorded in them.

## Run it

Docker and bash. The images are pinned by digest.

```sh
./run.sh test                                            # 85 tests + scripted agents, no API key
./run.sh eval --agent oracle                             # free: every task must pass
./run.sh eval --agent claude --reps 5 --judge both --budget-usd 2
./run.sh report runs/<run-dir>
./run.sh regrade runs/<run-dir> --view full --prompt strict --label full-strict-repeat   # re-judge saved episodes only
./run.sh charts                                          # the article's charts, from runs/ into charts/
```

`--budget-usd` is a hard stop: no new episode starts once the spend recorded from the API's
`usage` blocks reaches it. The key is passed to the container for one command only; on macOS
`run.sh` reads it from the keychain item `ANTHROPIC_API_KEY` when the variable is not set.

## What is in it

```
agent_eval/
  env.py       the world: schema, tools, the policy the agent is given
  tasks.py     23 tasks: seed, customer messages, what must and may change, an oracle trajectory
  grade.py     state grader (mutations, must/may) and the process check (verify before acting)
  agent.py     the agent under test: a manual tool loop over the Messages API
  scripted.py  oracle, null and liar agents: the harness is proven on them before any paid run
  judge.py     the transcript judge, in a narrative view and a full (tool calls included) view
  run.py       runs (task, rep) episodes; plumbing failures go to errors.jsonl, not to the score
  report.py    pass@1 with Wilson intervals, pass^k, failure shapes, judge agreement, cost (also as if uncached)
  regrade.py   runs a judge variant over saved trajectories, without calling the agent again
  charts.py    the article's charts as plain SVG, standard library only, read from runs/
tests/         the harness, graders and environment, including the checks above
runs/          the recorded runs the article quotes
charts/        the charts in the article, as generated by ./run.sh charts
```

Each run directory holds `config.json`, `results.jsonl` (one row per scored episode),
`errors.jsonl` (attempts that never produced a scorable episode), `summary.json`, and a full
trajectory per episode: every model call with its `usage` and request id, every tool call and
result, and the judge's verdicts with their reasons.

Re-grading experiments sit next to the run they re-judge, as `regrade-<label>.jsonl` and `regrade-<label>.json`:

| Run | Label | What it measured |
| --- | --- | --- |
| main run | `full-strict-repeat` | the full-view judge, same prompt, all 115 episodes again: 115 of 115 verdicts identical |
| main run | `narrative-lenient` | the narrative judge with the lenient prompt; the budget stopped it after 92 episodes |
| liar | `narrative-lenient` | the same lenient judge on the liar: no false passes |
